# Development commands

Every development command, for the lead Claude Code session and its subagents. Commands that call a paid model say so: run them only with the developer's approval and a USD limit. Add a command here only once it exists and works.

## Tests

Three commands (Vitest projects in `vitest.config.mts`: `unit` holds the pure tests; `integration` holds `tests/db/` and the real-document OCR checks):

- `npm run test:fast`: unit tests related to your uncommitted changes (Vitest `--changed`, through the import graph). About 1 to 6 s. Run it while implementing.
- `npm run test:integration`: integration tests related to your uncommitted changes, against Postgres. Up to about 23 s.
- `npm run test:full` (same as `npm test`): every test, about 27 s with 13 workers (it took 170 s run one file at a time). Run it before integrating a task, and at milestone integration and completion.
- One file: `npx vitest run tests/verify.test.ts`. Tests related to given source files: `npx vitest related server/src/evidence/store.ts --run`.

`--changed` follows imports only, so changes to `package.json`, the Vitest config, `drizzle/`, `data/eval/`, `tests/fixtures/`, `tests/db/database.ts`, `tests/db/workerDatabase.mts` or `.env` rerun everything (`forceRerunTriggers`). A change read through the file system rather than imported (for example a private fixture under `data/raw/`) is not detected: run `test:full`.

Each Vitest worker uses its own database, `<TEST_DATABASE_URL name without _test>_w<N>_test`, created on first use. Every file still drops and re-migrates it. The `eval-real` scripts keep using `TEST_DATABASE_URL` itself. To remove the worker databases: `for n in $(seq 1 16); do docker exec deposition-checker-db-1 dropdb -U deposition --if-exists deposition_checker_w${n}_test; done`.

- `npm install`: installs root deps; `postinstall` also installs `client/` deps
- `npm run dev`: server (`tsx watch`, port 3001), ingest worker and Vite client (port 5173, proxies `/api` to 3001)
- `npm run worker`: the worker on its own (ingest and analysis jobs; needs Postgres)
- `npx tsx scripts/eval-review.ts build|import`: builds the human review set (tracked references in `data/eval/review-set-v1.json`, testimony in the git-ignored sheet `data/eval/review/review-set-v1.csv`), or copies the filled-in sheet back; no API call. Retrieval code must never read this set
- `npx tsx scripts/interrupt-analysis.ts --analysis <id>`: closes out an analysis whose worker is gone, counting any open request in full; no API call
- `npx tsx scripts/demo.ts [--fresh]`: with `npm run dev` running, stores the synthetic fixture cases and starts demo analyses (Ellison, Webb) through the API; no model calls
- `npx tsx scripts/demo-case.ts --email <account email>`: seeds the hand-authored multi-witness demo case (`server/src/data/demoCase.ts`: two witnesses, two sessions each, eight prepared example assessments) into that account, through the real ingestion, verification and scoring; writes the sessions' original text to `data/uploads`; no model calls; a second run changes nothing. See README, "Multi-witness demo case"
- `npx vitest run -t "<test name>"`: one test
- `npm run typecheck`: `tsc --noEmit` over `server/`, `scripts/` and `tests/`, then the client tests (`tests/client/tsconfig.json`, with the client's compiler settings)
- `npm run build --prefix client`: typechecks and builds the client
- `npm run db:up` / `npm run db:down`: start or stop Postgres in Docker
- `npm run db:generate`: write a new SQL migration to `drizzle/` after changing `server/src/db/schema.ts` (review the SQL, then commit it)
- `npm run db:migrate`: apply migrations to the database in `DATABASE_URL`
- `npx tsx scripts/ingest.ts <file.pdf> --case <name> --witness <name> [--taken-on YYYY-MM-DD]`: ingest one PDF into the database in `DATABASE_URL`; re-running it on the same file replaces that deposition's rows instead of duplicating them
- `npx tsx scripts/pathb.ts (--case-id <id> | --case <name>) --witness <name> [--deposition <id>] [--mode all_terms|rare_terms] [--limit 15] [--lines 8]`: preview Path B pairs from the database in `DATABASE_URL` (read-only); a case name must match exactly one case and witness, and `--deposition` must be a ready deposition of that witness
- `npx tsx scripts/hybrid.ts estimate|report|pool (--case-id <id> | --case <name>) --witness <name> [--deposition <id>] [--a <id> --b <id>]`: card cost estimate, stored coverage and topic report, or both paths and the union as counts; no API call. `discovery [--distractors 60] [--capacity 30] [--mode rare_terms|all_terms]`: the synthetic discovery evaluation with mock models (wipes `TEST_DATABASE_URL`); no API call. `cards … --deposition <id> --budget-name <n> --budget-limit <usd> [--max-chunks 2]` and `topics … --budget-name <n> --budget-limit <usd>` make paid Haiku calls: run them only with approval
- `npx tsx scripts/direct-benchmark.ts estimate`: the synthetic evaluation's plan and cost, no API call. `score --analysis <id> --suite whitfield|webb` scores a finished analysis, no API call. `run --execute --approved-usd <n>` makes paid Fable batch calls on synthetic testimony: run it only with approval
- `npx tsx scripts/cross-benchmark.ts estimate --set data/eval/<set>-cross-v1.json --root <documents dir>`: the cross-witness evaluation's sessions, label resolution and cost range for Fable, Opus and Sonnet; no API call. `score --report <file> --root <dir>` re-scores a saved run, no API call. `run … --model fable|opus|sonnet --approved-usd <n> --execute` makes one paid batch call per comparison: run it only with approval. Reports (they quote testimony) go to the git-ignored `data/eval/review/cross/`
- `npx tsx scripts/direct-model.ts stored --analysis <id> [--labels data/eval/hutchinson-discrepancies-v1.json]`: re-checks an analysis's stored direct answer and, with `--labels`, scores labelled discrepancies for discovery and classification separately; no API call. `score --report <file> --labels <file>` scores a saved report, no API call. `run --analysis <id> --model opus|fable --approved-usd <n> --execute` makes one paid batch call on that analysis's sessions without changing the analysis (needs `ALLOW_PAID_CALLS=true` on that command): run it only with approval. Reports go to the git-ignored `data/eval/review/direct-model/`
- `npx tsx scripts/evidence.ts index [--case-id <id>] [--refresh]`: fills (or recomputes) the evidence fields of stored exchanges; `coverage --case-id <id>`, `search <words> --case-id <id> [--witness-id|--session-id|--document-id <id>]`, `get <exchange id> [--case-id <id>]` and `context <exchange id> [--lines 5]` read the index; `export-lines --deposition <id> --out data/raw/fixtures/<name>.json` saves a stored file for the real-fixture tests; `attribution --document-id <id>` explains non-verified exchanges; `parser-audit` lists stored documents with artifacts a later parser fixed (read-only); `reprocess --document-id <id> [--execute] [--accept-impact]` re-reads one in place (a dry run unless `--execute`; refuses to remove findings unless `--accept-impact`); `correct --document-id <id> [--expect-lines <page:line,…>]` is the safe correction's dry run (`server/src/evidence/correction.ts`: the whole correction under the current parser, rolled back; prints the plan, the integrity checks and the plan hash); `correct --document-id <id> --execute --plan-hash <hash> --expect-lines <page:line,…> [--backup-dir data/raw/backups]` executes a reviewed dry run (refuses while an analysis or case run of the case is unfinished, holds the document so the database refuses other writes to its evidence, then corrects, quarantines and verifies in one transaction; refuses, changing nothing, if anything differs from the plan); `rollback --migration <correction id>` restores the state before a correction from its backup (refuses if the document changed since); `release --migration <hold id>` releases a hold left by a crash, after checking nothing changed; `quarantine --document-id <id> --reason "<why>" [--findings <ids>]` quarantines findings on a superseded source, changing no evidence row; `integrity --document-id <id>` lists broken references into a document's exchanges (read-only); `reprocess` refuses whenever it would delete a reviewed finding; `exclude --document-id <id> --reason legacy_parse|duplicate|misfiled [--duplicate-of <id>]` leaves a stored copy out of new analyses, retrieval and the evidence index, keeping it and its findings (a duplicate names the active copy of the same file in the case); `eval-real` runs the real-data evaluation in `TEST_DATABASE_URL` (wipes it) and fails if a fixture file is missing or a check fails. No API calls. `scripts/ingest.ts … --session-of <deposition id>` stores a file as the next part of that deposition's session
- `npx tsx scripts/evidence-rehearsal.ts create --template <db> --name <x_rehearsal_y>`, `splits --db <copy> --uploads <dir> --backup data/raw/<dir> --out data/raw/<file>.json`, `findings --db <copy> …`, `drop --name <copy>`: rehearses evidence corrections on a disposable copy of a database (names must contain `_rehearsal_`; the copy is migrated, the template never written). `splits` runs interruption, recovery, worker coordination, dry run, execute, the split checks, idempotence and rollback on every document holding a confirmed bare-Q line; `findings` accounts for every document with findings and applies the quarantine policies. No model or API call
- `npx tsx scripts/db-snapshot.ts dump --db <db> --out data/raw/<dir>/<file>.dump`, `restore --file <dump> --into <new _rehearsal_ name>`, `verify --a <db> --b <db>`: a full-database snapshot (pg_dump custom format, with its SHA-256), restored only into a new disposable database, and compared table by table (plus guard triggers, constraints, ledger, epochs, quarantine, reviews and broken references). Uses pg_dump from PATH or inside `PG_DOCKER_CONTAINER`
- `npx tsx scripts/evidence-bench.ts write --db <x_rehearsal_y> [--without-guards] [--fresh] --out data/raw/<file>.json` and `correct --db <copy> --document-id <id> --uploads <dir> --out …`: benchmarks migration 0039's guards (bulk ingestion, fact units, candidate/verdict/finding persistence, concurrent writes, fenced writes) and the correction and rollback, on disposable databases only
- `npx tsx scripts/ui-rehearsal-seed.ts --db <x_rehearsal_ui> --uploads <dir> --out data/raw/<file>.json`: a disposable database with a verified reviewer, the demo case and quarantined findings, for checking the lawyer UI in a browser
- `npx tsx scripts/facts.ts plan --case-id <id>`: units, due units, requests, tokens and planned cost of Stage 2 extraction for a case's active documents; no API call, no writes. `coverage --case-id <id>`: units by status, facts indexed, rejected and stale, measured tokens and cost. `eval-real`: the hand-authored fact records through the real pipeline in `TEST_DATABASE_URL` (wipes it), no API call, fails if a fixture file is missing or a check fails. `run --document-id <id> --approved-usd <n> --execute` makes paid Haiku calls (needs `ALLOW_PAID_CALLS=true`): run it only with approval
- `npx tsx scripts/retrieval-embed.ts embed|score [--frozen data/raw/retrieval/frozen-v1] [--out data/raw/retrieval/agent-a] [--reps qac,qc,a] [--strip] [--center]`: local MiniLM embeddings (`@huggingface/transformers`; model and revision pinned in `server/src/retrieve/minilm.ts`, read from the git-ignored `data/raw/models/` with remote loading off; the script header shows the one-time download) as a retrieval path over a frozen benchmark. `embed` writes `neighbours-E_minilm_<rep>[_s][_c].json` and `rankings-…json` with an on-disk vector cache; `score` prints every path's per-query ranks of the labelled pairs and the fused top-5 pools. No API call
- `npx tsx scripts/facts-pilot.ts plan|report [--set data/eval/facts-pilot-v<n>.json]`: a real-model Stage 2 pilot's windows, units, requests and planned cost, or its report (recall candidates, compatibility, source validity, repeatability; testimony, so written to git-ignored `data/raw/`); no API call. `run --set <file> --approved-usd <limit> --execute` makes paid Haiku calls under the pilot's budget (needs `ALLOW_PAID_CALLS=true`): run it only with approval
- `npx tsx scripts/target-trace.ts --db <_rehearsal_ or _test database> [--pads 0,1,2] [--json data/raw/<file>]`: free, read-only. Traces each known target (limo/SUV, C01, C02) through production's case pool: eligibility, pool rank and the per-item cut that admits it, triage, the packet-v1 packet and stretch-v2 request, and whether its decisive lines are shown; `--pads` measures stretch padding (decisive lines in the target's own unit, requests, tokens, projected cost). No model call
- `npx tsx scripts/retrieval-probe.ts [--facts] [--json]`: the independent retrieval feasibility probe over every real fixture document in `TEST_DATABASE_URL` (wipes it): full text, LSA, question-centered and anchor paths, fused, with the known pairs' global and per-query ranks and per-item candidate budgets; `--facts` adds the pilots' indexed facts from `DATABASE_URL` as a fifth signal; no API call. Reports go to git-ignored `data/raw/retrieval/`
- `npx tsx scripts/retrieval-eval.ts --frozen <dir> [--paths <file>...] [--pools <file>...] [--benchmark <file>...] [--packets <file>...] [--overhead <tokens>] [--case-pattern <regex>] [--group] [--no-frozen-pools] [--out <dir under data/raw>] [--json]`: the independent retrieval evaluator over a frozen corpus (`server/src/retrieve/frozen.ts`) and any extra path or pool files: integrity checks, each labelled pair's rank in both directions per path, fused and with each path removed, pool holdings and budgets by category and target class (direct, needs context, unclassified), review burden and projected tokens to reach each target, coverage by witness and session pair, packet-set coverage, sizes and tokens (`--packets`, Agent 5 PacketSet, or `--group` to group each pool with Agent 5's default settings), every pool also restricted to within-case candidates (`--case-pattern`, an evaluation option), path contribution, an unlabelled sample (to `--out` only), runtime and memory; controls and exploratory pairs reported apart, counts only; protocol in `data/eval/retrieval-protocol-v2.md`. `--compare <old frozen dir> --frozen <new dir> [--benchmark-before <file>...] [--benchmark <file>...]` diffs two corpus versions: items same, changed, removed (with their fate) and added per document, and every labelled pair's side mapping. `--build-heldout <cross labels> --frozen <dir> --write <file>` resolves line labels to a corpus's items (`data/eval/simpson-resnick-heldout-v1.json`); `--build-fixture <cross labels> --root <dir> --write <file>` turns phrase labels into an evidence fixture for `scripts/retrieval-freeze.ts` (`data/eval/independent-cross-v1-fixture.json`). No database, model or API call
- `npx tsx scripts/retrieval-triage.ts --variant <name> [--frozen <dir>] [--pool <file>] [--max-pairs <n>] [--out <dir under data/raw>]`: triages a candidate pool (`server/src/retrieve/triage.ts`; defaults measured on both corpora: no rare-word gate, two partner passages per item, no budget) and writes the kept pool and every deferral with its stage and reason; no API call
- `npx tsx scripts/retrieval-group.ts [--out data/raw/retrieval/round2/agent-5] [--pools data/raw/retrieval/lead/pools]`: groups the lead's candidate pools into bounded evidence packets (`server/src/retrieve/grouping.ts`, experimental: issue clusters joined by two shared rare features and a core feature, residual stars kept to one other session; every pool pair in a packet or listed as uncovered with its reason) and prints projected calls and input tokens against pair-by-pair adjudication over a sweep of item and token bounds, with labelled pairs co-packeted and packets mixing different cases; writes `sweep.json`, `packets-<pool>.json` and `samples-<pool>.txt` (quotes testimony) under the git-ignored `data/raw/`. No API call
- `npx tsx scripts/retrieval-pools.ts --frozen <dir> --name <n> --out <dir under data/raw> [--extra <neighbours file>...] [--drop <path>...] [--per-item 5]`: builds a fused candidate pool from a frozen corpus's paths plus extra ones (e.g. MiniLM); `npx tsx scripts/retrieval-triage-sweep.ts` measures triage variants on both corpora's five-path pools; no API call
- `npx tsx scripts/retrieval-rerank.ts --frozen <dir> --pool <file>... --out <dir under data/raw> [--models ce,nli] [--benchmark <file>...]`: experimental local reranking (`server/src/retrieve/rerank.ts`, pure; models loaded only in `rerankModels.ts`: ms-marco-MiniLM-L-6-v2 relevance and nli-deberta-v3-xsmall contradiction cross-encoders, pinned and SHA-256 checked, read from `data/raw/models/` with remote loading off; the script header shows the one-time download). Scores both directions, windows long passages, and writes the same candidates in new orders (never fewer) plus per-candidate scores, for `retrieval-eval.ts`; no API call
- `npx tsx scripts/retrieval-factual.ts --frozen <dir> --out <dir under data/raw> [--benchmark <file>...] [--union <pool file> --reserve <k>] [--show <item key>...]`: the experimental numeric, temporal and polarity path `F_factual` (`server/src/retrieve/factual.ts`, pure: typed values and yes/no-resolved claims from question, answer and context, paired across sessions when a compatible value differs or polarity is opposed on shared subject words); writes `neighbours-F_factual.json`, `rankings-F_factual.json` and, with `--union`, that pool plus F's own top k per item outside the fusion; no API call
- `npx tsx scripts/rescore-direct.ts --analysis <id> [--write]`: scores stored direct findings with the evidence-strength checklist; no API call
- `npx tsx scripts/adjudicate.ts fixtures|list|show|estimate …`: store the synthetic Webb evaluation (`webb-synthetic-v1`), list candidates, print a packet with its verdicts and findings, or estimate worst-case and measured expected cost; no API call. `run --candidate <id> --budget-name <n> --budget-limit <usd> [--effort medium] [--prompt adjudicate-v1|adjudicate-v2]` makes one paid Sonnet call: run it only with approval
- Database tests in `tests/db/` run only when `TEST_DATABASE_URL` is set (it must name a database ending in `_test`; the tests wipe each worker's copy of it); otherwise they are skipped

Requires a `.env` with `ANTHROPIC_API_KEY`, `DATABASE_URL` and `TEST_DATABASE_URL`. Live analyses call a model only when `ALLOW_PAID_CALLS=true` is also set; leave it unset in development and tests. See `.env.example`, whose database URLs match `docker-compose.yml`. Add new commands here only once they exist and work.
- `npx tsx scripts/packet-benchmark.ts sample|dry-run`: the Milestone 2 packet-versus-pairwise evaluation. `sample` freezes the pilot sample (`data/eval/packet-pilot-v1.json`, item keys and input checksums only); `dry-run` loads both corpora's fixtures into `TEST_DATABASE_URL` (wipes it), builds every request from stored lines, runs both arms with the label-blind mock, verifies, scores, and prices the paid pilot from the serialized requests; no API call. Reports quote testimony, so they go to the git-ignored `data/raw/packet-pilot/`. `subset --from <sample> --packets c1:<id>,... --out <file>` freezes a smaller sample (the calibration is `data/eval/packet-calibration-v1.json`); `prepare-db --database pilot|rehearsal` creates that persistent database (`deposition_checker_pilot` or `deposition_checker_pilot_rehearsal`, never ending in `_test`, so tests can't wipe it), migrates it without dropping anything and loads both corpora's fixtures once; `run --mock --approved-usd <n> --database rehearsal --sample <file>` rehearses the paid loop offline; `--prompt packet-v1|packet-v2` selects the contract (default `packet-v1`; v2 loads each passage's adjacent exchanges); `rescore --run <dir> --database pilot|rehearsal` re-verifies a finished run's saved outputs under the contract it used and writes `report-rescored.json` and `pairs.json` (missed targets split into `evidence_incomplete` and `interpretation`), no API call; `run --plan ...` prints the request plan and finish check without sending; `--reuse <run dir>` reuses identical answered requests; `--repeat c1:<id>,...` sends repeatability requests after the main pass; `run --execute --approved-usd <n> --database pilot --sample <file>` is the paid run (needs `ALLOW_PAID_CALLS=true` on that command; records every call in the pilot database and `calls.jsonl`): run it only with approval
- `npx tsx scripts/case-run.ts --database-env <ENV_VAR> --case <id> --plan|--mock`: whole-case runs (`server/src/jobs/caseRun.ts`) in this process. The database comes from the named environment variable and is never defaulted; pointing it at `DATABASE_URL`'s database under another name is refused. `--plan` builds the case pool and packets, writes nothing and projects the cost (Milestone 2 calibration rates); `--mock` runs the whole case with the label-blind mock (no model, no budget, verdicts labelled `fixture`). **Paid:** `--live --budget <usd> --execute` (needs `ANTHROPIC_API_KEY` and `ALLOW_PAID_CALLS=true`; the command counts as the confirmation), and `--resume <runId> [--budget <usd>] [--retry-uncertain] --execute` on a live run (`--retry-uncertain` also retries packets whose request may already have been billed). Run those only with approval and a USD limit. Over HTTP, see `docs/case-run-api.md` (create, confirm, poll, findings, resume, cancel). `--concurrency <n>` (default 1) sends n packets at once, paced by the `PROVIDER_*` limits from the environment. `--economy` (with `--mock` or `--live`) uses economy execution through the Message Batches API (half price, up to 24 hours); `--mock --economy` uses the fake batch provider, free. **Paid, and off until `ALLOW_ECONOMY_ANALYSIS=true`:** `--live --economy --budget <usd> --acknowledge-retention --execute` (the provider keeps batch data 29 days); the command checks the batches every `CASE_RUN_BATCH_POLL_SECONDS` until the run stops, Ctrl-C is safe, and `--resume <runId> --execute` carries on. `--stretch` uses the experimental whole-stretch contract (needs `ALLOW_STRETCH_V2=true`; with `--mock` it is free)
- `npx tsx scripts/case-run-bench.ts --database-env PERF_DATABASE_URL --load`, then `... --latency-ms 100 --rate-limit-every 50 --concurrency <n> [--pool-max 10] [--profile-queries] [--label x]`: free, mock-only throughput benchmark of a whole-case run on the real fixtures. The database's name must end in `_perf_test` (it is written to; `--load` wipes it). A fake provider priced as the packet model (so budgets, `llm_calls` and settlement follow the paid path) answers with the label-blind mock after a fixed latency, and every Nth packet's first request gets a 429. Prints one JSON line: timings, packets per minute, queries and pool saturation (`--profile-queries`: the statements sent per packet), retries, duplicates, budget and a findings fingerprint to compare runs. Says nothing about the real provider's throughput. `--execution batch [--batch-size 100] [--batches-in-flight 10]` runs the same case in economy execution against the fake batch provider (every batch ends at once), for a fingerprint to compare with a standard run; its timing is the pipeline's import cost, never the provider's turnaround
- `npx tsx scripts/screening-benchmark.ts [--raw data/raw] [--out data/raw/screening/<name>]`: the Milestone 3 offline screening benchmark. Screens both frozen within-case packet sets with every strategy, checks pair accounting and provenance, and reports targets reached, session coverage and projected cost per budget, real and synthetic apart; fails if an input file changes during the run. No model, API or database call. Output is git-ignored (it names testimony items)
- `npx tsx scripts/audit-findings.ts [--previous <report of the previous verifier>] [--out data/raw/audits/<file>.json]`: read-only (refuses a writable connection) recomputation of every stored finding against what is stored, with each difference's cause; `--previous` is the evidence for attributing source or attribution changes to the current verification version. No API call
- `npx tsx scripts/packet-size-analysis.ts [--root data/raw/packet-pilot] [--runs pilot-run:packet-v1,v2-eval:packet-v2]`: packet-versus-single-pair error rates by packet size from saved paid outputs only (paired by pair); writes `data/raw/packet-pilot/size-analysis/`. No API call
- `npx tsx scripts/packet-benchmark.ts compare --runs <dir>,<dir> --sample <file> [--out data/raw/<file>.json]`: scores several finished runs on one sample from their saved `pairs.json` (run `rescore` first), with exact-match and review-oriented metrics (correct contradiction, surfaced for review, appropriate uncertainty, unsupported evidence, missed; controls: incorrect contradiction, surfaced for review, correct). Read-only; no database, model or API call
